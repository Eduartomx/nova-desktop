# Nova v0.9.9 — Resident Mode & Runtime Lifecycle

## Objetivo

Nova 0.9.9 separa la vida del proceso de la visibilidad de la ventana. Ocultar Nova ya no significa cerrar Agent, hotkeys, wake word, Perception, Gaming Awareness o Qwen.

La implementación mantiene la arquitectura 0.9.x y evita una reescritura general de Agent/Tools/UI. El nuevo núcleo es `RuntimeLifecycleManager`; las capas existentes solo delegan los puntos de entrada que necesitan distinguir ocultar de terminar.

## Arquitectura

### RuntimeLifecycleManager

Archivo: `nova/assistant/runtime_lifecycle.py`

Estados explícitos:

- `starting`
- `running`
- `hidden`
- `shutting_down`
- `stopped`

Entradas principales:

- `request_window_close()` — botón X. Si Resident Mode y la bandeja están disponibles, ejecuta `withdraw()` y pasa a `hidden`.
- `show_window()` — restaura y enfoca la ventana desde hotkey, bandeja o segunda ejecución.
- `request_shutdown(reason)` — salida real idempotente.

El cierre real se programa en el scheduler de Tk y ejecuta, con aislamiento de errores por componente:

1. bloquear nuevas tareas/comandos y listeners de entrada;
2. detener grabación, voz y wake word;
3. detener Gaming Awareness, Perception y servicios locales asociados;
4. cerrar Browser Agent;
5. ejecutar `flush()` en componentes que lo soporten;
6. aplicar `unload_on_exit` de Qwen;
7. detener la bandeja;
8. liberar hook de sesión e instancia única;
9. destruir Tk.

No se usan `sleep` para coordinar este lifecycle. Una segunda llamada a shutdown no inicia una segunda secuencia.

### Bandeja

Archivo: `nova/assistant/tray_controller.py`

Dependencia nueva: `pystray`; Pillow ya formaba parte de Nova.

El icono usa `run_detached()`. El menú expone apertura, estados cacheados de Qwen/Gaming, precarga/liberación de Qwen, comprobación de actualización, estado/alternancia de inicio con Windows y salida real.

Las operaciones potencialmente lentas se lanzan fuera del hilo Tk. Mostrar/ocultar/salir se delega a `RuntimeLifecycleManager`, cuyo scheduler devuelve la operación de UI al hilo principal.

Si `pystray` no inicia, `available=False` y Resident Mode no oculta la ventana con X; se usa shutdown normal para evitar un proceso invisible.

### Instancia única

Archivos:

- `nova/assistant/instance_lock.py`
- `nova/assistant/instance_commands.py`

Antes de importar `core_runtime`, `app.py` intenta adquirir un lock exclusivo bajo `%LOCALAPPDATA%\Nova\runtime`. En Windows la exclusividad depende de `msvcrt.locking`: el archivo persistente no es un PID file y no es la fuente de propiedad; el kernel libera el lock si el proceso termina.

Una segunda ejecución no crea Tk, Agent, hotkeys ni servicios. Escribe de forma atómica el comando `show` en un buzón local del perfil del usuario y termina con código 0. La primera instancia consume el buzón mediante `root.after`.

Comandos permitidos:

- `show`
- `shutdown_for_update`
- `status`

El buzón requiere una estructura exacta, timestamp reciente y descarta contenido malformado u obsoleto. No abre sockets ni servidores de red.

### Inicio con Windows

Archivo: `nova/assistant/autostart.py`

Se usa exclusivamente:

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\NovaDesktop`

La entrada apunta a la instalación actual y añade `--background`. No requiere administrador. `subprocess.list2cmdline()` genera el comando para soportar rutas con espacios.

La fuente de verdad de estado es la entrada real de HKCU. La migración de `config.json` añade defaults pero nunca crea la entrada del registro. `start_with_windows` permanece `false` salvo acción explícita del usuario.

### Windows shutdown/logoff

Archivo: `nova/assistant/windows_session.py`

Nova responde rápidamente a `WM_QUERYENDSESSION` y, cuando recibe `WM_ENDSESSION`, envía al lifecycle una razón `windows_shutdown`, `windows_logoff` o `windows_closeapp`. El hook restaura el WndProc anterior al salir.

### Updater

Archivos:

- `nova/updater/update_runner.py`
- `nova/updater/nova_updater.py`
- `nova/assistant/ui_workspace.py`

La UI lanza `update_runner.py --parent-pid <PID>` y después ejecuta `request_shutdown("update")`. El supervisor espera la terminación real.

Si el supervisor se ejecuta desde CMD sin PID, prueba el lock. Si Nova está residente, escribe `shutdown_for_update` y espera a que el kernel permita adquirir el lock antes de modificar archivos.

`nova_updater.py` mantiene el modelo GitHub-native: Release/tag, tree Git, SHA de blobs, staging, backup/rollback, actualización de `requirements.txt` y validación Python. Una ejecución interactiva directa delega al supervisor. La ruta `--yes` queda como ejecución interna después de haber coordinado el cierre.

El supervisor relanza una sola instancia con `app.py --post-update`, visible incluso cuando el inicio habitual es `--background`.

## Configuración

```json
"resident_mode": {
  "enabled": true,
  "close_to_tray": true,
  "start_with_windows": false,
  "start_hidden": false,
  "notifications": true
}
```

Compatibilidad: configuraciones antiguas reciben estas claves faltantes sin modificar hotkeys ni activar HKCU.

## Rutas deterministas

`agent_fast_routing.py` resuelve sin LLM frases explícitas equivalentes a:

- `Nova, ¿estás ejecutándote en segundo plano?`
- `Nova, ocúltate en la bandeja`
- `Nova, muéstrate`
- `Nova, inicia con Windows`
- `Nova, no inicies con Windows`

La modificación de autostart solo se acepta para frases explícitas predefinidas. Conversaciones ambiguas no cambian el sistema.

## Notificaciones y privacidad

La bandeja aplica deduplicación/cooldown por evento. Las notificaciones válidas son genéricas y no incluyen prompts, respuestas, títulos completos de ventanas, contenido de pantalla, tokens ni secretos.

Se contemplan actualización disponible/terminada, errores importantes y tareas largas completadas en segundo plano. Una respuesta normal del LLM no genera una notificación.

## Diagnóstico

Nova Doctor agrega Resident Mode y muestra:

- estado del lifecycle;
- ventana visible/oculta;
- bandeja activa/degradada;
- instancia adquirida;
- estado real de inicio con Windows;
- motivo de salida anterior cuando exista;
- cantidad/estado de errores recientes sin exponer contenido sensible.

## Pruebas automáticas

Cobertura incorporada o ampliada:

- `running → hidden → running`;
- X no detiene Gaming/Perception/hotkeys ni descarga Qwen;
- bandeja fallida provoca shutdown normal;
- shutdown idempotente;
- lock de segunda instancia y recuperación posterior;
- buzón malformado;
- autostart idempotente con rutas con espacios;
- bandeja mock e icono único;
- órdenes residentes deterministas;
- instancia adquirida antes de `core_runtime`;
- `--background` / `--post-update`;
- updater solicita `shutdown_for_update`;
- relanzamiento único post-update;
- ejecución directa del updater delegada al supervisor;
- `WM_QUERYENDSESSION` / `WM_ENDSESSION` con backend simulado.

CI conserva la suite completa Ubuntu y amplía la puerta `windows-latest` para Resident Mode junto con updater, Gaming Awareness, Instant Wake/hotkeys y núcleo nativo. Las suites sensibles se repiten para detectar carreras.

## Riesgos residuales a validar en Windows real

- comportamiento del icono pystray en el área de iconos ocultos de diferentes configuraciones de Windows 11;
- restauración de foco desde una aplicación exclusiva/fullscreen;
- wake word/F9 mientras la ventana está `withdrawn`;
- WM_ENDSESSION real durante cierre de sesión o apagado;
- interacción entre cierre de un juego, restauración de Qwen y una ventana de Nova oculta;
- política antivirus/seguridad que pudiera impedir la entrada HKCU o el lock del archivo local.

## Plan manual Windows

1. Abrir Nova normalmente.
2. Pulsar X y confirmar que desaparece de la barra de tareas pero queda en bandeja.
3. Abrirla con el hotkey configurado.
4. Restaurarla desde la bandeja/doble clic.
5. Probar wake word y F9 con la ventana oculta.
6. Abrir un juego y verificar Gaming Mode con Nova oculta.
7. Ejecutar Nova de nuevo y comprobar que solo restaura la instancia existente.
8. Activar inicio con Windows, reiniciar sesión y comprobar inicio oculto.
9. Desactivar inicio con Windows y comprobar que desaparece la entrada.
10. Buscar actualizaciones desde bandeja sin instalar una versión inexistente.
11. Salir desde la bandeja y comprobar que no queda un proceso Nova.
12. Volver a iniciar y verificar que no existen listeners/servicios duplicados.
