# Nova v0.9.3 — LLM Performance Intelligence

## Objetivo

Separar la latencia real de Ollama en componentes medibles antes de cambiar modelo, cuantización, contexto o política de GPU a ciegas.

## Métricas

Cada llamada local a `/api/chat` puede registrar, cuando Ollama las devuelve:

- tiempo total de pared observado por Nova;
- `total_duration` del servidor;
- `load_duration`;
- `prompt_eval_count` y `prompt_eval_duration`;
- `eval_count` y `eval_duration`;
- tokens/s calculados para prompt y generación;
- número de mensajes, tools expuestas y caracteres aproximados del contexto;
- muestra puntual de utilización GPU y VRAM antes/después si `nvidia-smi` está disponible.

Las duraciones de Ollama se convierten de nanosegundos a milisegundos antes de persistirse.

## Privacidad

`data/llm_performance.db` NO contiene columnas para prompt, respuesta, contenido de mensajes, argumentos de herramientas, títulos de ventana, tokens secretos ni claves API. Solo guarda metadatos técnicos y conteos.

Las conexiones SQLite son de vida corta y se cierran explícitamente para no dejar handles innecesarios en Windows.

## Ventanas de tiempo

Nova Doctor separa:

- sesión actual;
- últimos 15 minutos;
- última hora;
- últimas 24 horas.

El profiler general también añade un `session_id`. Los eventos históricos siguen disponibles en ventanas largas, pero ya no contaminan el diagnóstico principal de una sesión recién iniciada.

## Diagnóstico de causa

El monitor puede señalar heurísticamente:

- `cold_start`: carga del modelo relevante;
- `prompt_heavy`: evaluación del prompt/contexto consume una fracción alta;
- `generation_heavy`: la generación domina la duración;
- `gpu_memory_pressure`: la muestra de VRAM cruza el umbral configurado;
- `tool_context_heavy`: muchas tools y prompt grande;
- `unstable_or_timeout`: proporción elevada de fallos;
- `unattributed_slow`: lentitud sin causa dominante en las métricas disponibles.

Estas etiquetas son diagnóstico técnico heurístico, no una garantía causal.

## Benchmark explícito

`Nova, prueba tu rendimiento` ejecuta exactamente tres casos locales y acotados:

1. respuesta corta;
2. razonamiento breve;
3. selección con una tool mínima.

El benchmark nunca se ejecuta automáticamente. Usa `num_predict` para limitar la generación y no envía información a Groq, Cerebras, ChatGPT ni OpenAI.

## Configuración opcional

Los defaults viven en `assistant/llm_performance.py` y pueden sobrescribirse en `config.json` con un bloque como:

```json
{
  "llm_performance": {
    "enabled": true,
    "max_events": 1800,
    "gpu_sampling": true,
    "gpu_sample_timeout_seconds": 1.2,
    "cold_start_ms": 750,
    "slow_response_ms": 6000,
    "prompt_heavy_ratio": 0.30,
    "generation_heavy_ratio": 0.45,
    "gpu_pressure_percent": 85.0,
    "benchmark_max_tokens": 64
  }
}
```

No hace falta agregar este bloque para usar la función; esos son los valores predeterminados.

## Comandos

```text
Nova, prueba tu rendimiento.
Nova, ¿por qué Ollama tarda tanto?
Nova, rendimiento de Qwen de esta sesión.
Nova, muestra tu rendimiento de los últimos 15 minutos.
```

La intención de 0.9.3 es obtener datos suficientes para decidir en una versión posterior si el problema real está en generación, contexto, cold starts o presión de GPU/VRAM antes de activar optimizaciones adaptativas o Gaming Awareness.
