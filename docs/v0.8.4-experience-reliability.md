# Nova v0.8.4 — Experience & Reliability Loop

v0.8.4 cierra el ciclo de aprendizaje de Skills: una habilidad ya no conserva reputación indefinidamente solo porque funcionó en el pasado.

## Objetivo

El motor observa únicamente resultados verificados de ejecuciones de Skills y mantiene una fiabilidad por **versión**. Si una Skill se actualiza, la nueva versión comienza sin heredar los fallos/éxitos de la versión anterior.

Estados:

- `unproven`: todavía no tiene ejecuciones verificadas en esa versión.
- `learning`: tiene historial, pero todavía insuficiente.
- `stable`: el historial reciente es consistente.
- `watch`: existe evidencia negativa reciente o confianza intermedia.
- `degraded`: fallos consecutivos o tasa reciente demasiado baja.
- `stale`: llevaba funcionando, pero no se ha revalidado dentro del periodo de obsolescencia configurado.

El índice de fiabilidad es heurístico; no representa una probabilidad calibrada de éxito.

## Política de seguridad

Nova **no** deshabilita una Skill automáticamente y **no** modifica su playbook silenciosamente.

Una Skill con `trust_level=verified` puede volver a `draft` si acumula evidencia negativa o queda obsoleta. Esa degradación solo cambia su nivel de confianza; conserva la definición, historial y estado habilitado para que el usuario pueda revisarla.

La corrección del procedimiento debe verificarse antes de crear una nueva versión.

## Privacidad

`data/skill_reliability.db` guarda únicamente:

- `skill_id`
- `run_id`
- versión de la Skill
- workspace id opcional
- resultado (`prepared`, `success`, `failure`, `returned`)
- timestamps
- métricas agregadas y motivo de revisión

No guarda prompts, argumentos de ejecución, resultados de herramientas, summaries, instrucciones del playbook, respuestas de Groq/ChatGPT ni secretos.

## Valores predeterminados

La configuración opcional `skill_reliability` acepta:

```json
{
  "enabled": true,
  "rolling_window": 12,
  "minimum_runs": 3,
  "stable_threshold": 0.78,
  "degraded_threshold": 0.55,
  "consecutive_failures_review": 2,
  "stale_days": 60,
  "auto_demote_verified": true,
  "max_events": 2500,
  "inject_context": true,
  "max_prompt_items": 3
}
```

Si el bloque no existe en un `config.json` anterior, estos defaults se aplican automáticamente desde el módulo.

## Herramientas

- `skill_reliability_status`
- `skill_reliability_report`
- `skill_reliability_review_queue`

Ejemplos de lenguaje natural:

- `Nova, estado de fiabilidad de Skills.`
- `Nova, ¿qué habilidades están fallando?`
- `Nova, ¿qué Skills están obsoletas?`
- `Nova, fiabilidad de la habilidad Diagnóstico rápido.`

La ventana **🧩 Skills** muestra además el estado de fiabilidad y una advertencia cuando una habilidad requiere revisión.
