# Nova v0.9.0 — Native Core Migration

## Objetivo

Eliminar la dependencia oculta de cuatro archivos históricos que hasta 0.8.x existían en instalaciones antiguas, pero no podían reconstruirse desde GitHub: `agent.py`, `tools.py`, `ui.py` y `task_engine.py`.

## Nuevo contrato

0.9.0 convierte esos cuatro módulos en archivos administrados por GitHub y cambia `architecture_status()` para exponer `github_managed_core`. `legacy_local_contract` queda vacío por compatibilidad con consumidores antiguos y `unmanaged_core_files` debe ser `[]`.

Un checkout limpio puede importar el core y ejecutar `install_core_runtime()` sin depender de archivos copiados de una instalación anterior.

## Migración gradual

0.9.0 no intenta absorber en una sola Release todas las capas `agent_*`, `tools_*` y `ui_*`. Siguen instalándose por dominio desde `core_runtime.py`. Esto separa dos riesgos:

1. **propiedad/recovery del core** — resuelto en 0.9.0;
2. **eliminación progresiva de monkey-patching** — trabajo de 0.9.x.

La meta es que cada futura migración pueda eliminar un adaptador solo después de pruebas de equivalencia del dominio correspondiente.

## LocalAgent

El nuevo `LocalAgent` administra el loop Ollama `/api/chat`, historial local, selección de herramientas, tool calls, errores de conexión/timeout y trazas mínimas. Los system prompts específicos de Workspace, Semantic Memory, Perception, Skills, Confidence, Expert y Reliability siguen montándose mediante sus capas estables.

## LocalTools

El core incluye herramientas base de sistema, procesos, archivos, memoria, screenshot puntual, portapapeles, apertura de apps/URLs, búsqueda web y PowerShell con una barrera determinista para patrones destructivos/seguridad.

`tools_desktop.py` preserva capacidades históricas administradas:

- Browser Agent Playwright con perfil persistente `data/browser_profile`;
- worker dedicado de navegador para evitar compartir objetos sync entre hilos;
- lectura/inspección/click/fill/teclas/pestañas/back/reload;
- ventanas y UI Automation (`uia_snapshot`, `uia_click`, `uia_type`);
- fallback de mouse/teclado.

El contenido de web/UI sigue siendo dato externo no confiable y los controles sensibles no conceden autorización.

## AssistantUI y voz

La UI base vuelve a vivir en GitHub y conserva los atributos/métodos que necesitan las extensiones actuales. Mantiene:

- Ctrl+Alt+Space;
- Ctrl+Shift+Space;
- F9 push-to-talk;
- faster-whisper local;
- TTS local;
- wake word local opcional.

Wake word no descarga modelos en background. Si el modelo configurado no existe, el asistente continúa funcionando por hotkeys/PTT.

## Task Engine

El nuevo `TaskEngine` mantiene persistencia de tareas/pasos/eventos, pausa/reanudación/cancelación, reintentos, límites de tiempo/tool-calls y `auto_replan` acotado por `max_replans`.

La verificación 0.9.0 sigue siendo conservadora y ligera: un paso no debe considerarse exitoso si la respuesta informa fallo, falta de conexión o confirmación pendiente. Las capacidades de Confidence/Skills/Continuity continúan añadiendo señales por sus dominios.

## Rendimiento de arranque

`ui_semantic.py` deja de hacer una comprobación activa de disponibilidad de modelo durante startup (`semantic_status(refresh=False)`). Nova Doctor conserva la comprobación explícita con refresh.

## Pruebas

Además de la suite histórica, 0.9.0 añade smoke tests para:

- presencia física de los cuatro cores en el repositorio;
- `architecture_status()` sin contrato local;
- lectura/escritura restringida y bloqueo de PowerShell destructivo;
- loop de tool-calling de LocalAgent con Ollama simulado;
- persistencia de Task Engine con MemoryStore real;
- contrato base de AssistantUI sin crear una ventana en CI headless;
- instalación completa de `core_runtime` en un subprocess limpio y presencia de Browser/Skills/Confidence tools.

## Lo que 0.9.0 todavía NO hace

- no elimina todos los adaptadores `agent_*`, `tools_*`, `ui_*`;
- no cambia automáticamente workspaces por detección;
- no elimina las confirmaciones de seguridad;
- no convierte respuestas externas en instrucciones confiables;
- no resuelve todavía todo el hardening pendiente de rutas Windows/reparse points de Workspace Intelligence.

Esas migraciones se abordarán de forma incremental en 0.9.x.
