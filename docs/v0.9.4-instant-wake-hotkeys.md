# Nova v0.9.4 — Instant Wake & Hotkeys

## Objetivo

Nova 0.9.4 ataca el cuello de botella medido en 0.9.3: el primer mensaje puede ser mucho más lento que los siguientes cuando Ollama necesita cargar Qwen nuevamente en memoria.

La actualización añade un **LLM Warm Manager** y reemplaza los atajos globales basados en Espacio por combinaciones configurables que no interfieren con usos comunes de `Ctrl+Espacio`.

## Instant Wake

Al iniciar Nova, el Warm Manager puede precargar el modelo local en segundo plano mediante una petición de Ollama con `messages: []`.

Esta precarga:

- no contiene un prompt del usuario;
- no genera una conversación artificial;
- no llama a Groq, Cerebras, ChatGPT, OpenAI ni otros servicios externos;
- prepara el mismo modelo local configurado para el Agent.

La política predeterminada de 0.9.4 es:

```json
{
  "llm_warm": {
    "enabled": true,
    "preload_on_start": true,
    "startup_delay_seconds": 0.35,
    "keep_alive": "20m",
    "request_timeout_seconds": 30.0,
    "status_timeout_seconds": 2.5,
    "unload_on_exit": true
  }
}
```

`keep_alive: "20m"` mantiene Qwen cargado después de una inferencia durante una ventana razonable, pero evita reservar VRAM indefinidamente. Cada llamada normal de Nova también renueva ese keep-alive.

Al cerrar Nova, el modelo se descarga de Ollama por defecto (`unload_on_exit: true`).

## Estado del modelo

Nova consulta `/api/ps` de Ollama para saber si el modelo sigue cargado y, cuando Ollama entrega el dato, muestra la VRAM ocupada por ese modelo y su expiración.

La interfaz muestra un estado compacto como:

```text
LLM: preparando…
LLM: listo · 6607 MB VRAM
LLM: descargado
```

Nova Doctor añade además una sección **LLM Warm Manager** con:

- cargado / descargado / precargando;
- modelo;
- keep-alive;
- VRAM reportada;
- duración de la última precarga;
- expiración reportada por Ollama;
- último error de warm-up, si existe.

Comandos deterministas disponibles:

```text
Nova, ¿Qwen está cargado?
Nova, precarga Qwen.
Nova, libera la VRAM.
```

El último comando descarga explícitamente el modelo local de Ollama con `keep_alive: 0`.

## Nuevos atajos

Los defaults de 0.9.4 son:

```text
Abrir Nova:               Ctrl+Alt+N
Abrir Nova con contexto:  Ctrl+Alt+Shift+N
Push-to-talk:              F9
```

Las instalaciones que todavía tengan los antiguos defaults basados en Espacio se migran automáticamente:

```text
Ctrl+Espacio             -> Ctrl+Alt+N
Ctrl+Alt+Espacio         -> Ctrl+Alt+N
Ctrl+Shift+Espacio       -> Ctrl+Alt+Shift+N
Ctrl+Alt+Shift+Espacio   -> Ctrl+Alt+Shift+N
```

## Editor de hotkeys

La ventana principal incorpora **⚙ Atajos**.

Desde allí se pueden editar las dos combinaciones globales y aplicarlas **sin reiniciar Nova**. Antes de guardar, Nova valida que:

- exista al menos una tecla principal además de modificadores;
- no se usen teclas desconocidas;
- principal y contexto no sean idénticos;
- no se intente registrar `Ctrl+Alt+Delete`, reservado por Windows.

Si Windows o `pynput` rechazan una combinación, Nova conserva el atajo anterior en lugar de dejar al usuario sin acceso global.

## Privacidad

Instant Wake es completamente local. La precarga usa una petición vacía de Ollama y la telemetría de rendimiento existente continúa guardando únicamente métricas técnicas, no prompts ni respuestas.

## Preparación para Gaming Awareness

0.9.4 no activa todavía detección automática de juegos ni libera el LLM automáticamente cuando se abre uno. Sí deja preparada la infraestructura necesaria:

- estado explícito cargado/descargado;
- descarga voluntaria del modelo;
- política centralizada de keep-alive;
- medición de VRAM;
- warm-up reutilizable después de liberar recursos.

Esto permite que una versión posterior implemente Gaming Awareness sin mezclar esa política con el núcleo de inferencia.
