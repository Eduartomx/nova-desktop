# Nova v0.9.5 — Gaming Awareness

## Objetivo

Hacer que Instant Wake conviva con juegos sin mantener varios GB de VRAM ocupados por Qwen cuando el juego necesita ese margen.

0.9.5 no convierte a Nova en un overlay ni inyecta código en juegos. La detección usa únicamente metadatos locales de Perception Engine y procesos del sistema.

## Detección

Gaming Awareness combina varias señales:

- ventana externa clasificada como `game` por Perception Engine;
- procesos configurados como Fortnite, Roblox, VRChat o Minecraft for Windows;
- ejecutables dentro de bibliotecas conocidas de Steam, Xbox Games o Epic Games;
- `javaw.exe` con argumentos compatibles con Minecraft/Forge/Fabric.

Para evitar cambios por transiciones breves se usan tiempos de permanencia al entrar y salir del modo juego.

## Política de VRAM

El valor predeterminado es `release_policy: smart`.

En esa política Nova libera Qwen cuando:

- el juego está en primer plano; o
- la VRAM usada cruza el umbral configurado; o
- queda menos VRAM libre que el margen configurado.

Antes de liberar el modelo Gaming Awareness:

1. suspende nuevas precargas automáticas;
2. cambia temporalmente el `keep_alive` de inferencias a `0`;
3. espera si hay una precarga o inferencia activa;
4. descarga Qwen mediante la API local de Ollama;
5. conserva la razón de la decisión y una estimación de VRAM recuperada.

Si el usuario consulta a Nova mientras juega, la inferencia sigue siendo posible. Gaming Awareness no interrumpe una inferencia activa; con la política predeterminada el modelo vuelve a liberarse al finalizar la llamada.

## Restauración

Cuando el juego desaparece durante el tiempo de salida configurado:

- se elimina el override temporal de `keep_alive`;
- se habilita de nuevo la precarga;
- Perception vuelve a su frecuencia normal;
- si Gaming Mode fue quien descargó Qwen, Nova lo precarga de nuevo en segundo plano después de unos segundos.

Una descarga manual del usuario no se interpreta como una descarga de Gaming Mode.

## Perception throttle

Perception Engine no hace screenshots continuos, pero 0.9.5 reduce igualmente su polling de metadatos mientras Gaming Mode está activo. El default cambia temporalmente de 1100 ms a 2500 ms sin modificar la preferencia persistente.

## Control del usuario

Comandos deterministas:

```text
Nova, ¿estás en modo juego?
Nova, activa modo juego.
Nova, desactiva modo juego.
Nova, vuelve a modo juego automático.
Nova, mantén Qwen cargado aunque esté jugando.
Nova, libera Qwen cuando juegue.
Nova, ¿por qué liberaste Qwen?
```

La UI añade `🎮 Juego`, donde se puede elegir modo automático/forzado/desactivado, política `smart/always/never` y si Qwen debe permanecer cargado durante juegos.

## Configuración

```json
{
  "gaming_awareness": {
    "enabled": true,
    "auto_detect": true,
    "poll_seconds": 2.0,
    "enter_dwell_seconds": 2.5,
    "exit_dwell_seconds": 7.0,
    "release_policy": "smart",
    "auto_release_llm": true,
    "keep_llm_loaded_during_game": false,
    "llm_keep_alive_during_game": 0,
    "vram_release_percent": 65.0,
    "vram_min_free_mb": 2600.0,
    "restore_preload_after_game": true,
    "restore_delay_seconds": 4.0,
    "perception_poll_ms_during_game": 2500
  }
}
```

## Privacidad y seguridad

Gaming Awareness no:

- lee memoria de otros procesos;
- inspecciona tráfico del juego;
- instala hooks o DLLs;
- inyecta código;
- captura teclado;
- usa screenshots para detectar juegos;
- envía datos a servicios externos.

La telemetría GPU reutiliza las muestras puntuales locales que Nova ya puede obtener mediante `nvidia-smi`.
